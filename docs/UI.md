# Интерфейс 0.5.0

Ориентир — присланный владельцем скриншот Telegram Desktop. Серверные настройки и логика ключей при изменении оформления не менялись.

- Левое меню 72 px: все чаты, пользовательские папки, непрочитанные, закреплённые и действие **ПАПКИ**. Меню сверху открывает настройки.
- В списке остаются поиск, поиск пользователей и создание комнаты. Убраны большая брендовая шапка и второй набор фильтров. Строка чата 68 px; выделение занимает всю ширину.
- Ширина списка по умолчанию 380 px. Разделитель поддерживает мышь, стрелки, Home/End; диапазон 280–640 px. Значение сохраняется локально. На экранах до 1200 px ширина ограничена доступным местом; на мобильном экране список занимает всю ширину.
- На мобильном экране папки и фильтры доступны в горизонтальной строке с действием **ПАПКИ**.
- Заголовок переписки 54 px на Windows. Информация о комнате закрыта при запуске и открывается по нажатию на название или значок информации. Неизвестное число участников не показывается как ноль.
- Сообщения одного автора группируются в пределах пяти минут и одного календарного дня. Удалённые события и сообщения без доступного ключа разделяют группы. Имя показывается в начале группы, инициалы — у последнего входящего сообщения группы. Имя и фото берутся из участников комнаты; Matrix ID/инициалы служат fallback.
- Короткая история прижата к низу. Длинная история виртуализирована; смещение списка учитывается при вычислении видимых сообщений. Время и отметка отправки размещены рядом с текстом. Одна галочка означает передачу серверу; две используют реальные receipt. В группе это отметка хотя бы одного другого участника, а не обещание прочтения всеми.
- Строка ввода плоская, на всю ширину. Enter отправляет, Shift+Enter добавляет новую строку. Рядом — файл, Markdown, emoji, микрофон и отправка. Кнопки звонков показываются в комнатах с двумя joined-участниками.
- Ошибки показываются сверху, чтобы не закрывать повторную отправку внизу. Действие **Открыть зашифрованные комнаты** остаётся небольшим текстом внизу списка.

Снимки в `releases/` получены в Chromium с отдельным тестовым IPC. В них вымышленные данные; в production нет деморежима. WebView2 и состояние конкретного аккаунта после обновления 0.5.0 отдельно не проверялись.

В 0.5.0 есть media viewer/player/save, глобальная очередь файлов, голосовой рекордер, room info с участниками/ролями/медиа/pins, поиск по серверной истории, профили/устройства/аккаунты, масштаб и фоны. Native Android Back/share подключены отдельно от браузерной адаптивной вёрстки.

## Диалоги и выбор сообщений

После явного подключения ключей последние доступные сообщения закрытых комнат загружаются в фоне двумя запросами одновременно. Открывать каждый чат не требуется; read receipt фоновая загрузка не отправляет. Если ключ конкретного последнего сообщения отсутствует, показывается «Нет ключа для последнего сообщения». Текст не сохраняется в LocalStorage или открытом UI SQLite.

DM определяется через Matrix `m.direct`, а не только число участников. Его фото берётся у другого пользователя; при отсутствии фото остаются инициалы. Двухместная группа без `m.direct` сохраняет фото комнаты. В профиле и ПКМ по DM доступна «Моя подпись контакта»: подпись хранится локально для пары сервер/аккаунт, применяется к сообщениям, спискам и заголовкам, сбрасывается кнопкой и не отправляется в Matrix. Между устройствами подписи не синхронизируются.

ПКМ по чату открывает «Закрепить чат»/«Открепить чат»; значок булавки также постоянно доступен в строке. Закреплённые идут выше других чатов и видны в фильтре «Закреп.». Закрепление чата отличается от закреплённого сообщения в комнате.

ПКМ по сообщению → «Выделить сообщение» включает флажки. Можно добавить сообщения нажатием на фон, флажком или повторным контекстным действием. Панель показывает количество и лимит 100; «Выделить загруженные» берёт первые 100 доступных сообщений. Удалённые/нерасшифрованные не выбираются. Escape или крестик отменяют выбор. Пересылка идёт по времени, при частичном сбое повтор использует прежние transaction ID и пропускает уже доставленные события. Закрытие окна останавливает следующие отправки, но не отзывает уже принятый запрос. Для перехода из E2EE в обычную комнату требуется подтверждение.

Переписка и информация используют разные React keys и явные позиции grid. Это устраняет воспроизведённое дублирование панелей при смене комнаты с открытой информацией. Невидимые кнопки над сообщением не перехватывают клики.
