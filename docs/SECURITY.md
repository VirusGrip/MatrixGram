# Безопасность 0.2.0

Последнее указание владельца возвращает поддержку E2EE и заменяет прежний запрет из версии 0.1.0. Matrix SDK 0.19.1 собран с `e2e-encryption` и SQLite crypto-store; default features отключены. `npm run check:policy` проверяет нужные функции SDK, отсутствие автоматического bootstrap идентичности/backup и CSP.

## Необязательное открытие комнат

Обычный вход не открывает мастер ключей. Локальная настройка `e2ee_enabled` по умолчанию false. До явного включения ядро блокирует историю и запись в известных E2EE-комнатах. При этом SDK готовит криптографическое устройство и выполняет стандартный обмен публичными ключами устройства.

Новые комнаты и личные чаты создаются без `m.room.encryption`. При записи в существующую E2EE-комнату формат и шифрование события выбирает SDK. Состояние проверяется перед записью; ошибка проверки или неизвестное состояние не дают сделать plaintext fallback. При изменении состояния комнаты требуется дождаться sync. Проверка состояния и отправка не являются атомарной серверной операцией.

## Подключение ключей

- Recovery key или пароль secret storage передаётся только в SDK `recovery.recover()`. Методы reset_identity, recover_and_reset, recover_and_fix_backup и удаление backup не вызываются.
- Альтернатива — зашифрованный файл экспорта Matrix/Element до 10 МБ и его пароль. Временный файл содержит исходный зашифрованный экспорт; после операции выполняется его удаление. Расшифровку и импорт делает SDK.
- Recovery key и пароли не сохраняются в LocalStorage, настройках или журнале. Полученные Rust-строки защищены Zeroizing; поля интерфейса очищаются после операции.
- Автоматическое создание backup и cross-signing выключено. Восстановление существующей идентичности может подписать собственное устройство через Matrix API.
- SAS/QR-верификации пока нет. Если ключ сообщения отсутствует, отображается понятное сообщение, а не утверждение об успешной расшифровке.

## Локальное хранение и обновление

SDK store расположен в `accounts/{uuid}/sdk-e2ee-v1/` и открывается с отдельным случайным паролем. Пароль и Matrix-сессия находятся в Windows DPAPI, привязанном к пользователю Windows. При загрузке сессии 0.1.0 без этого поля создаётся новая защищённая папка SDK с прежним Matrix device ID; прежний UI-кеш и черновики сохраняются. Формат старой сессии проверен автоматически; обновление реального установленного клиента требует отдельной проверки.

Расшифрованная E2EE-история передаётся интерфейсу в памяти и не записывается в открытый UI SQLite-кеш. Черновики известных E2EE-комнат на Windows сохраняются через DPAPI. Обычный кеш, имена комнат и папки остаются открытыми. Выход не является безопасным стиранием локальных данных.

Android пока не сохраняет токен и пароль SDK store между процессами: нужен Keystore. Постоянная криптография Android и runtime не проверены.

## WebView и сеть

Токен не передаётся в WebView, пароль входа не сохраняется. Ошибки SDK заменяются фиксированными сообщениями. HTTPS и проверка TLS обязательны; HTTP используется только в локальных тестах. У приложения нет диагностического логирования секретов.

CSP разрешает собственные скрипты и локальный IPC. Сообщения отображаются текстом React без dangerouslySetInnerHTML. Нет удалённых скриптов, общего доступа к shell или файловой системе. Файл ключей выбирается стандартным пользовательским file input.

Поиск вызывает Client-Server user directory; видимость результатов определяет сервер. Папки меняют локальные данные. Конфигурация Synapse, PostgreSQL, TURN и служб не меняется.
