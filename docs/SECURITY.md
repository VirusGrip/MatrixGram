# Безопасность и отсутствие E2EE

## Обязательная политика

Последние указания владельца заменяют разделы об E2EE из `original-spec.ru.md`. Сквозное шифрование не поддерживается и не включается ни на одной платформе.

1. Cargo отключает default features Matrix SDK. `npm run check:policy` проверяет итоговое дерево зависимостей на отсутствие `matrix-sdk/e2e-encryption`, `matrix-sdk-base/e2e-encryption` и `matrix-sdk-sqlite/crypto-store`.
2. Создание комнат использует стандартные private_chat/public_chat presets без события шифрования.
3. Интерфейс скрывает переписку и ввод в комнатах с подтверждённым E2EE.
4. Ядро блокирует отправку, правки, реакции и redaction в зашифрованных комнатах. Перед записью запрашивает текущий `m.room.encryption`; только Matrix `M_NOT_FOUND` допускает незашифрованную отправку. Ошибка сети, отказ доступа и неизвестное состояние не допускают отправку. Известный зашифрованный кеш блокирует запись даже при последующем ответе M_NOT_FOUND.
5. Ключи Element не импортируются, существующие комнаты не переводятся в открытый режим. Сервер не настраивается.

Некоторые транзитивные криптографические типы SDK и библиотеки TLS остаются в Cargo.lock. Их наличие не включает Matrix E2EE: соответствующие features и криптографическое хранилище Matrix отключены. Самодельной криптографии нет.

Между проверкой состояния комнаты и отправкой существует сетевой интервал: Matrix API не даёт атомарной операции «проверить состояние и отправить». Комната может измениться в этот момент. Для комнат, в которых другие клиенты планируют включать E2EE, следует использовать клиент с поддержкой E2EE. Политику неизвестного состояния и переход после последнего sync проверяют отдельные интеграционные тесты.

## Сессия и данные

На Windows DPAPI защищает сериализованную сессию привязкой к текущему пользователю Windows. Пароль после входа не сохраняется; токен остаётся в Rust. Выход сначала отзывает сессию на сервере и затем удаляет защищённый файл. Если сервер недоступен, клиент сообщает об ошибке и сохраняет возможность повторить выход.

При повреждении файла сессии доступен локальный сброс на экране входа. Локальный сброс не отзывает токен на сервере: ненужное устройство нужно завершить через совместимый Matrix-клиент. Кеш сообщений остаётся на диске после выхода; это не безопасное стирание данных.

На Android постоянная сессия намеренно недоступна до реализации Keystore. Приложение не записывает токен открытым текстом. Runtime Rustls certificate verifier, Android lifecycle и восстановление после завершения процесса должны проверяться на устройстве до выпуска APK.

Токен не отправляется в HTML, URL, LocalStorage или логи. Ошибки SDK заменяются фиксированными сообщениями перед IPC. В текущем приложении нет логирования запросов. При добавлении диагностических журналов запрещено логировать пароли, токены, TURN credentials и тела личных сообщений.

HTTPS обязателен для входа. Адрес должен быть origin без логина, пароля, пути, query и fragment. TLS-проверка не отключается. Локальный HTTP разрешён только внутри тестовых конструкторов wiremock.

## WebView

HTML сообщений отображается как обычный текст; `dangerouslySetInnerHTML` не используется. Нет загрузки удалённых скриптов, навигации по ссылкам сообщений, доступа к shell, файловой системе или общих HTTP-разрешений из WebView. CSP ограничивает connect-src локальным IPC, script-src — собственными файлами.

Вложения, внешний просмотр документов, открытие ссылок, камера, микрофон и push ещё не добавлены; разрешения под них сейчас не выдаются. Добавление требует проверки MIME, размеров и путей, а также защиты от сохранения файлов за пределами выбранной папки.
