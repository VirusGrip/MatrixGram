# Производительность 0.5.1

Дата: 11 ноября 2026. [Полные метрики JSON](performance-0.5.1.json). Сравнение с 0.5.0, commit `27398dc`; старая версия запускалась из отдельного checkout с тем же тестовым стендом. Компиляция во время основного сравнения не выполнялась.

| Сценарий | 0.5.0 | 0.5.1 | Отношение задержек |
|---|---:|---:|---:|
| Обновление → два кадра, медиана | 831 мс | 132 мс | 6.3× |
| Обновление → два кадра, p95 | 1026 мс | 139 мс | 7.4× |
| Поиск среди 5 000 чатов | 905 мс | 103 мс | 8.8× |
| SQLite: запись 100 000 событий | 2866 мс | 1629 мс | 1.8× |

Это измерения одного стенда, не обещание такого ускорения на каждом компьютере. Startup зависит от Vite transform/prebundle и в таблицу ускорения не включён. Чтение 100 000 событий SQLite: 747 → 697 мс; 1 000 запросов последнего сообщения: 59 → 31 мс.

## Стенд и нагрузка

- AMD Ryzen 5 5600 6-Core Processor, 12 логических CPU, 16 ГБ RAM, Windows build 10.0.26200, Node v24.22.1.
- Chromium Playwright, Vite development build и отдельный IPC adapter, CPU throttling ×4. 5 000 комнат, 20 000 сообщений открытой переписки, ещё 40 000 событий в 200 других комнатах, 2 000 участников и 1 000 receipts. Серия из 40 обновлений по 25 событий с новыми снимками списка комнат. Между обновлениями ожидаются два requestAnimationFrame. Поиск измеряется от ввода запроса до появления результата.
- В основной нагрузке панель информации о комнате закрыта; её собственная проекция и медиа-галерея отдельно не профилировались. После поиска открывается другой чат; проверяется доступность конца истории. В DOM остаются менее 45 строк чатов и 100 сообщений: виртуализация не разворачивает весь набор.
- До и после серии Chromium выполняет GC; retained JS heap сравнивается с лимитом прироста 80 МиБ. В основном прогоне конечный heap 25.2 → 28.6 МиБ. WeakMap-кеш и индексы используют немного дополнительной памяти ради снижения CPU. Это JS heap, не RAM всего Windows-процесса.
- Отдельный тест: 200 закрытых комнат ×50 сообщений. Превью загружаются после явного включения E2EE; одновременно не больше двух фоновых history-запросов, read receipts отсутствуют. Криптографию fixture не измеряет.
- SQLite: временная локальная БД, 200 комнат ×500 событий, WAL и штатные транзакции. Затем 1 000 previews, чтение 100 000 событий, redaction/stale replay, четыре конкурентных writer с повторяющимися событиями. Проверяются количество записей, отсутствие дублей и сохранение удаления. Это `cargo test` dev profile; не release SDK benchmark.

Расширенный прогон: 500 обновлений / ещё 12 500 событий, одновременно со сборками. Пройден; медиана 132 мс, p95 154 мс, максимум 465 мс. Heap после GC: 28.0 → 31.7 МиБ. Этот прогон проверяет устойчивость; с ним не рассчитывается ускорение относительно baseline. Он длится около минуты, не заменяет длительный endurance test.

## Воспроизведение

```powershell
npm ci
npm exec -w @matrixgram/client -- playwright install chromium
npm run test:load
cargo test --workspace --locked cache_load_100000_events -- --ignored --nocapture
```

Для расширенного прогона:

```powershell
$env:MATRIXGRAM_LOAD_BURSTS='500'
$env:MATRIXGRAM_PERF_LABEL='extended'
npm run test:load
Remove-Item Env:MATRIXGRAM_LOAD_BURSTS
Remove-Item Env:MATRIXGRAM_PERF_LABEL
```

Количество обновлений ограничено диапазоном 1–1 000, по умолчанию 40. JSON пишется в `apps/client/performance-results/browser-<label>.json`, default label `current`. SQLite печатает `LOAD_CACHE_JSON`. Нагрузочный сценарий исключён из обычного `test:e2e`; Windows CI содержит отдельные шаги, сам workflow здесь не запускался.

Проверки блокируют ошибки JS, потерю доступности истории, разворачивание всех строк в DOM, p95 обновления/поиск более 5 секунд и retained heap growth более 80 МиБ. Это широкие пороги регрессий для разных машин, не целевая задержка продукта.

## Изменения

WeakMap переиспользует проекцию неизменившейся истории и освобождает старые записи после GC. Поиск использует Map исходных имён и Set папок/закреплений. Map сообщений/участников устраняет повторные линейные проходы для receipts, ответов и авторов; DateTimeFormat переиспользуется. Неизменившийся Chat пропускает родительские render, typing не включает таймер без печатающих участников. Одновременные запросы одной history-страницы объединяются с изоляцией по сессии и освобождением после ошибки. SQLite сохраняет прежние транзакции и правила удаления, переиспользуя prepared statements.

Реальный WebView2 process CPU/RAM, Android lifecycle, Megolm под нагрузкой, сетевые задержки Synapse, TURN и длительная работа ещё требуют измерений на отдельных тестовых аккаунтах/устройствах. Продакшен-сервер этой проверкой не нагружался.
