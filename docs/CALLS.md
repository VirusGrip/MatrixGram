# WebRTC, существующий TURN и план звонков

Готовых звонков в версии 0.2.0 нет. Кнопки, имитирующие вызов, отсутствуют.

Ядро содержит метод `Account::turn_servers()`: он запрашивает стандартный `GET /_matrix/client/v3/voip/turnServer` с текущей Matrix-сессией и возвращает ICE URLs и временные username/password с TTL. Метод проверяется через wiremock. Реальные данные TURN вашего сервера без входа в тестовый аккаунт не проверялись; адрес и пароли не захардкожены.

## Следующий этап: один на один

1. Реализовать Matrix VoIP `m.call.invite`, `m.call.answer`, `m.call.candidates`, `m.call.hangup`, version 1 и party_id согласно [Matrix VoIP](https://spec.matrix.org/latest/client-server-api/#voice-over-ip).
2. WebRTC RTCPeerConnection работает в WebView; короткоживущие TURN credentials передаются только модулю вызова и обновляются по TTL. SDP и ICE отправляются через Rust с той же проверкой незашифрованной комнаты.
3. Запрашивать разрешения микрофона/камеры только при пользовательском действии. Завершение вызова закрывает peer connection, останавливает tracks и таймеры.
4. Проверить взаимный вызов с совместимым Matrix-клиентом, работающим с legacy Matrix VoIP. Современный Element может использовать другой стек; совместимость нельзя предполагать.
5. Проверить сценарии через TURN с `iceTransportPolicy: 'relay'`, NAT, отказ разрешений, истечение invite, отклонение, потерю сети и завершение удалённой стороной.

Для звонков один на один дополнительная инфраструктура не планируется до проверки существующего TURN. MatrixRTC/LiveKit для групповых вызовов — отдельный проектный этап. На сервере ничего не устанавливается и не меняется без отдельного разрешения владельца.
