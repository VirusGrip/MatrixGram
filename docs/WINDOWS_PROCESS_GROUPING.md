# Общая память и группировка процессов MatrixGram в Windows

Проверка: 17 ноября 2026, MatrixGram 0.5.4, Windows 11 Pro 10.0.26200, WebView2 157.0.4341.46.

## Что подтверждено

MatrixGram создаёт одно дерево: основной процесс → браузер WebView2 → renderer/GPU/utility/crashpad. В проверенной установке это 7 процессов. Чужие WebView2, например системный поиск Windows, в дерево MatrixGram не входят.

На вкладке «Процессы» при сортировке по памяти основной MatrixGram и его группа WebView2 отображаются отдельно. После переключения на сортировку по столбцу «Имя» пользователь подтвердил, что они объединяются. Существующая иерархия родителей корректна.

Практический вариант для этой машины: оставить сортировку по «Имя» и раскрыть MatrixGram — WebView2 входит в его группу. Это подтверждение пользователя, без повторного просмотра или захвата его экрана. Работа группировки при сортировке по памяти не исправлена.

Два последовательных замера частной резидентной памяти всего дерева дали 178,62 и 176,01 МиБ. В тот же период Element 1.12.33 после завершения временного updater занимал 368,57 МиБ. Это снимки текущих приложений без выравнивания открытой истории и нагрузки, не сравнительный benchmark.

## Ограничение Windows/WebView2

Проблема отдельной группы WebView2 зарегистрирована в открытых задачах:

- [Microsoft WebView2 #5628](https://github.com/MicrosoftEdge/WebView2Feedback/issues/5628).
- [Tauri #15567](https://github.com/tauri-apps/tauri/issues/15567).

В задаче Microsoft отмечено, что один вызов SetCurrentProcessExplicitAppUserModelID не исправляет группировку Task Manager. [Документация этого API](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-setcurrentprocessexplicitappusermodelid) описывает группировку панели задач; это не гарантия общей строки расхода памяти в диспетчере задач.

Единая ветка MatrixGram уже доступна на проверенной машине при сортировке по имени; изменение клиента для этого не потребовалось. Принудительное объединение при любой сортировке **не реализовано и не объявляется исправленным**. Новая версия с таким исправлением не выпущена.

[FAQ Microsoft](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/end-user-faq) предупреждает, что представление групп иногда некорректно при сортировке не по имени. Пользователь выполнил ручную проверку и подтвердил: «Нет, по имени объединяется». Это согласуется с описанным Microsoft ограничением; перебор AppUserModelID/MSIX сейчас не требуется.

После уточнения требования исследование продолжено. [Изолированный диагностический проект](../tools/windows-grouping-probe/README.md) использует те же Wry 0.57.1 и Tao 0.37.2, отдельный workspace без Matrix SDK и отдельный профиль каждого запуска. Пользователь предоставил скриншоты трёх режимов при сортировке по памяти: без явного ID, с ранним ID процесса, с ранним ID процесса и окна. Во всех случаях WebView2 остаётся отдельной группой. Эти изменения в клиент не перенесены.

Технические smoke-проверки ожидают IPC от самого локального HTML, проверяют чтение ID до/после создания WebView2 и завершают скрытый тестовый процесс. Проверка только события загрузки пустого `about:blank` заменена на проверку готовности документа. Четыре режима прошли smoke; Clippy с `-D warnings` и форматирование пройдены. Сами по себе эти результаты не проверяют группировку.

В установленном WebView2 157.0.4341.46 обнаружено имя feature `msWindowsTaskManager`. Для проверки подготовлены отдельный вариант теста и однократный launcher настоящего MatrixGram с `--disable-features=msWindowsTaskManager` только в окружении нового процесса. Флаг применился; пользователь сообщил, что отдельная группа WebView2 исчезла, но MatrixGram по-прежнему показывает около 40 МБ. Независимая сверка: 7 процессов, 164,61 МиБ всего, 37,48 МиБ основного процесса. Это не требуемая агрегация, вариант отклонён.

Глобальные настройки запуска приложения/окружения не менялись. [Microsoft предупреждает](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/webview-features-flags), что browser flags не предназначены для production и могут измениться. Обычный запуск стандартным ярлыком не получает диагностический флаг. Конкретное внутреннее правило группировки Task Manager пока не установлено.

Следующий подготовленный эксперимент — отдельный sparse package identity. Unsigned регистрация отклонена Windows с 0x80073D2B из-за executable activation. Signed-кандидат (3231 байт) и публичный семидневный сертификат готовы, подпись проверена. Signing key находится только в CurrentUser/My; TrustedPeople/TrustedRoot не изменялись, package registration отсутствует. Для проверки нужно отдельное разрешение на временный CurrentUser/TrustedPeople certificate и регистрацию изолированного тестового пакета; install/remove scripts проверяют конкретную identity/thumbprint/хеши. Работа package identity и группировка пока не подтверждены. Подробности и точный состав кандидата: [README диагностики](../tools/windows-grouping-probe/README.md).

Пользователь согласовал общий счётчик памяти в настройках как временный вариант. В исходниках 0.5.5 добавлен Windows-раздел «Память приложения»: общая частная резидентная ОЗУ, число процессов, PID и вклад каждого. Он не изменяет группировку Task Manager.

[0.5.5 опубликована](https://github.com/VirusGrip/MatrixGram/releases/tag/v0.5.5) 17 ноября 2026. Сборка и подписи проверены; интерфейс покрыт browser IPC-тестами. Счётчик показывает общее потребление независимо от сортировки диспетчера задач.

Сборщик использует Toolhelp для собственного дерева и PDH с английскими путями, без subprocess и повышения прав. Одноимённые процессы получают отдельные instance indices; индивидуальный ID Process повторно проверяется в той же коллекции, что Working Set - Private. Время создания проверяется до/после сбора. Ошибка или смена PID не превращается в нулевую/чужую память. Сумма неполных данных явно помечается.

[Живая сверка](memory-0.5.5-live.json) Windows 11: 7 процессов, 157,35 МиБ и такое же значение независимого Windows counter. Проверен сборщик из 0.5.5 на работающем клиенте 0.5.4; это не системный UI-тест установленной новой версии.

## Критерии готовности

1. В чистой установленной сборке Windows 10 и Windows 11 вкладка «Процессы» показывает MatrixGram с дочерними WebView2 и суммой памяти.
2. Проверяются запуск ярлыком/протоколом, сворачивание в трей, повторный запуск и выход. WebView2 других приложений не должны попадать в группу MatrixGram.
3. Вкладка «Сведения» может по-прежнему содержать отдельные exe; требование касается агрегированной ветки на вкладке «Процессы».
4. Только изменение метаданных, корректное дерево PID или успешная компиляция не считаются подтверждением исправления.
