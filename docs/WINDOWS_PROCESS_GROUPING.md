# Группировка процессов MatrixGram в Windows

## Подтверждённый результат

17 ноября 2026 пользователь проверил Windows 11 Pro 10.0.26200 / WebView2 157.0.4341.46: sparse package identity объединяет основной процесс и все дочерние WebView2 **внутри группы MatrixGram** на вкладке «Процессы», включая сортировку по памяти. Процессы и sandbox остаются отдельными, расход памяти суммируется.

Проверки выполнены последовательно:

1. Изолированный HTML probe с package identity: пользователь подтвердил общую группу и предоставил скриншот с семью процессами. Нативный GetCurrentPackageFullName подтвердил identity, HTML сообщил готовность через IPC.
2. Копия настоящего установленного MatrixGram 0.5.4 с тем же профилем: пользователь подтвердил группу MatrixGram, WebView2 внутри неё и обычные чаты.
3. После удаления временного доверия сертификату и приватного ключа новый процесс сохранил identity. Внешний exe заменён без переустановки identity-пакета; пользователь снова подтвердил группу и профиль.

18 ноября пользователь установил локальный кандидат 0.5.6 обычным установщиком и подтвердил группу MatrixGram, прежние чаты и переход по тестовому системному уведомлению. Установленный EXE побайтово совпал с payload проверенного кандидата. Пакет имеет статус Ok, временное доверие сертификату и приватный ключ отсутствуют. Перезагрузка Windows и Windows 10 ещё требуют проверки. Живой экран после запрета пользователя не просматривался; вывод о группировке основан на его ответах и присланных изображениях.

## Установка и обновление 0.5.6

[Документированный механизм Microsoft](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/grant-identity-to-nonpackaged-apps) присваивает обычному Win32 exe Windows package identity, сохраняя внешний каталог и существующий установщик. В `windows/client.manifest` записаны publisher/package/application ID; основной идентификатор Tauri и каталог данных не меняются.

Пакет `MadFrog.MatrixGram` имеет постоянную версию **1.0.0.0** и внешний exe `matrixgram.exe`. Его не пересобирают и не регистрируют заново с каждой версией приложения. В Git находятся подписанный MSIX, публичный сертификат и контрольные суммы. Приватный ключ уничтожен после создания; ключ Tauri updater остаётся отдельным прежним ключом.

При первой интерактивной установке предлагается настройка. Для экземпляров, обновлённых без диалога, доступно: **Настройки → Группировка процессов Windows → Настроить группировку**. Отказ сохраняет обычный работоспособный клиент и общий счётчик памяти. Тихая новая установка не запрашивает согласие и не добавляет доверие.

Настройка показывает явное Yes/No с выбором No по умолчанию, затем Windows UAC. Узкий помощник добавляет только встроенный end-entity сертификат в **LocalMachine/TrustedPeople** — область, которую требует [MSIX](https://learn.microsoft.com/en-us/windows/msix/package/create-certificate-package-signing). Он удаляет добавленное доверие после finish-file, завершения родителя или 180 секунд; существующее до настройки доверие сохраняется. Root CA не меняются, приватного ключа у помощника нет. Регистрация пакета выполняется в исходном пользовательском контексте.

Для уже работающего клиента требуется полный выход через меню «Выход» и новый запуск. Панель проверяет package identity текущего процесса и не объявляет группировку активной только по наличию настроечного файла.

NSIS hooks сохраняют регистрацию и узел внешнего каталога при `/UPDATE`. Обычное удаление снимает только собственный пакет с совпадающим publisher и внешним путём. Данные аккаунтов не удаляются. Смена каталога требует отдельной перерегистрации; исходная привязка восстанавливается при ошибке, насколько это позволяет ОС. Этот сценарий пока не проверен на устройстве.

Самоподпись статического MSIX не является публичным сертификатом Authenticode для EXE/NSIS и не обещает репутацию SmartScreen. Бесплатность достигается разовой подтверждённой настройкой, без постоянного доверия или нового серверного сервиса.

## Автоматические проверки

- Проверка SHA-256 статических файлов, CMS-подписи MSIX, закреплённого публичного signer и наличия timestamp. Проверка соответствия executable manifest и identity.
- Компиляция узкого C# помощника встроенным .NET Framework compiler; только публичный сертификат во встроенном ресурсе.
- Реальные production NSIS hooks выполняются на изолированной файловой fixture. Нативный File ID каталога до/после updater-delete совпадает. Обычный uninstall удаляет только собственную fixture. UAC и OS-регистрация в этом тесте не запускаются.
- Browser IPC проверяет явное действие, результат с необходимостью перезапуска, отказ/ошибку, активный native status и отсутствие Windows-кнопок на неподдерживаемой платформе.
- Для package identity Windows toast использует notifier текущего приложения; кнопка «Тестовое уведомление» позволяет проверить доставку и переход без отправки сообщений людям. Автотест этого маршрута использует fixture; реальная доставка тестового уведомления и клик после локальной установки подтверждены пользователем.

Воспроизведение:

```powershell
./scripts/prepare-windows-integration.ps1
./scripts/test-windows-integration.ps1
npm run test:e2e
cargo test --workspace --locked
```

## Что не сработало

Обычный Tauri/WebView2 корректно создаёт одно дерево PID, но Task Manager разделяет группы при сортировке по памяти. По имени пользователь подтвердил объединение. Открытые отчёты: [WebView2 #5628](https://github.com/MicrosoftEdge/WebView2Feedback/issues/5628), [Tauri #15567](https://github.com/tauri-apps/tauri/issues/15567).

Три изолированных режима AppUserModelID не помогли. Флаг `--disable-features=msWindowsTaskManager` скрывал отдельную группу WebView2, но не прибавлял её память: 37,48 МиБ основного процесса против 164,61 МиБ всего дерева. Этот флаг отклонён, в клиент не перенесён. [Диагностические исходники](../tools/windows-grouping-probe/README.md) сохранены; тестовые пакеты, доверие и приватный ключ удалены.

С 0.5.5 в настройках также есть суммарный счётчик частной резидентной ОЗУ через Toolhelp/PDH. [Живая независимая сверка](memory-0.5.5-live.json) дала 157,35 МиБ для семи процессов обоими способами. Этот счётчик остаётся полезен независимо от представления Task Manager.

## Проверка финального установщика

1. Выйти из текущего MatrixGram через «Выход», установить кандидат 0.5.6. Согласиться с первоначальной настройкой и UAC, если нужна группировка.
2. При сортировке по памяти раскрыть MatrixGram: основной процесс и все его WebView2 должны находиться внутри, с суммой ОЗУ. Чужие WebView2 не входят.
3. Проверить прежний профиль, ярлык, трей/выход, повторный запуск. Настройки должны показывать активную identity. Нажать «Тестовое уведомление», затем уведомление: открывается MatrixGram с панелью обновлений.
4. Проверить отсутствие добавленного сертификата в TrustedPeople после настройки, повторный запуск после перезагрузки, следующее обновление через приложение без новой настройки.
5. Отдельно повторить на чистой Windows 10 (build 19041+) и Windows 11. Успешная компиляция и браузерные тесты не подменяют эти проверки.
