# Общая память и группировка процессов MatrixGram в Windows

Проверка: 17 ноября 2026, MatrixGram 0.5.4, Windows 11 Pro 10.0.26200, WebView2 157.0.4341.46.

## Что подтверждено

MatrixGram создаёт одно дерево: основной процесс → браузер WebView2 → renderer/GPU/utility/crashpad. В проверенной установке это 7 процессов. Чужие WebView2, например системный поиск Windows, в дерево MatrixGram не входят.

В диспетчере задач Windows основной MatrixGram и его группа WebView2 отображаются отдельно. Это подтверждено непосредственно на вкладке «Процессы», а не выводится только из имён исполняемых файлов. Существующая иерархия родителей корректна; переименование или изменение родителей её не исправляет.

Два последовательных замера частной резидентной памяти всего дерева дали 178,62 и 176,01 МиБ. В тот же период Element 1.12.33 после завершения временного updater занимал 368,57 МиБ. Это снимки текущих приложений без выравнивания открытой истории и нагрузки, не сравнительный benchmark.

## Ограничение Windows/WebView2

Проблема отдельной группы WebView2 зарегистрирована в открытых задачах:

- [Microsoft WebView2 #5628](https://github.com/MicrosoftEdge/WebView2Feedback/issues/5628).
- [Tauri #15567](https://github.com/tauri-apps/tauri/issues/15567).

В задаче Microsoft отмечено, что один вызов SetCurrentProcessExplicitAppUserModelID не исправляет группировку Task Manager. [Документация этого API](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-setcurrentprocessexplicitappusermodelid) описывает группировку панели задач; это не гарантия общей строки расхода памяти в диспетчере задач.

Задача пользователя для следующего обновления — единая ветка MatrixGram с суммарной памятью. Она **пока не реализована и не объявляется исправленной**. Новая версия с этим исправлением не выпущена.

[FAQ Microsoft](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/end-user-faq) также предупреждает, что представление групп иногда некорректно при сортировке не по имени. На проверенной машине активна сортировка по памяти. Переключение на сортировку по имени не подтверждено: диспетчер задач имеет более высокий integrity level, чем UI helper, и обычный ввод не изменил сортировку. Повышение привилегий и обход ограничений не выполнялись. Этот диагностический вариант остаётся для ручной проверки.

Пользователь согласовал общий счётчик памяти в настройках как временный вариант. В исходниках 0.5.5 добавлен Windows-раздел «Память приложения»: общая частная резидентная ОЗУ, число процессов, PID и вклад каждого. Он не изменяет группировку Task Manager.

Сборщик использует Toolhelp для собственного дерева и PDH с английскими путями, без subprocess и повышения прав. Одноимённые процессы получают отдельные instance indices; индивидуальный ID Process повторно проверяется в той же коллекции, что Working Set - Private. Время создания проверяется до/после сбора. Ошибка или смена PID не превращается в нулевую/чужую память. Сумма неполных данных явно помечается.

[Живая сверка](memory-0.5.5-live.json) Windows 11: 7 процессов, 157,35 МиБ и такое же значение независимого Windows counter. Проверен сборщик из 0.5.5 на работающем клиенте 0.5.4; это не системный UI-тест установленной новой версии.

## Критерии готовности

1. В чистой установленной сборке Windows 10 и Windows 11 вкладка «Процессы» показывает MatrixGram с дочерними WebView2 и суммой памяти.
2. Проверяются запуск ярлыком/протоколом, сворачивание в трей, повторный запуск и выход. WebView2 других приложений не должны попадать в группу MatrixGram.
3. Вкладка «Сведения» может по-прежнему содержать отдельные exe; требование касается агрегированной ветки на вкладке «Процессы».
4. Только изменение метаданных, корректное дерево PID или успешная компиляция не считаются подтверждением исправления.
