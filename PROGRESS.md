# MatrixGram — прогресс 0.5.7

Дата: **18 ноября 2026**. Windows — основной клиент; Android — экспериментальная сборка. Наличие кода, подписи и автоматических тестов не означает проверки перехода между установленными версиями на устройстве.

## Файлы до 500 МиБ — кандидат 0.5.7

По последнему решению владельца лимит клиента — **524 288 000 байт (500 МиБ)** на отправку и скачивание. Авторизованный read-only GET media/config 18 ноября подтвердил такой же предел сервера. План увеличения до 2 ГБ отменён; Synapse/proxy не менялись, SSH-подключений не было.

- Большие исходящие файлы идут через бинарные IPC-блоки по 1 МиБ; Rust передаёт HTTP небольшими блоками по 256 КиБ. Подготовка шифруется SDK на диске, ключ остаётся в памяти. Обычные комнаты получают обычные байты, E2EE — шифротекст и стандартный Matrix descriptor; событие отправляет SDK.
- Входящие файлы сохраняются нативно, без большого base64/Blob в WebView. Проверяются объявленный и фактический размеры, SHA-256 E2EE. На Windows результат атомарно заменяет выбранный файл только после проверки; ошибка/отмена сохраняет прежний файл. Android использует SAF и файловые дескрипторы JNI, включая «Поделиться» без чтения целого файла в Kotlin.
- Прогресс, отмена, повтор отправки и продолжение при переходе между чатами. Серверный лимит проверяется перед отправкой; установка обновления блокируется во время передачи. Предпросмотр/аватары/запись голоса — до 25 МиБ; большие медиа сохраняются как файлы.
- Локальный нагрузочный прогон: настоящий зашифрованный файл 500 МиБ отправлен и скачан через loopback, результат сверён побайтово. 167,45 с, наблюдавшийся пик working set тестового процесса 22,12 МиБ (опрос 500 мс). Это замер отдельного теста, не установленного клиента и не сети Matrix. [Отчёт](docs/file-transfer-0.5.7-local.json).
- Локально прошли 66 Rust-тестов (50 core + 16 приложения), 43 frontend unit, основной набор из 70 browser-тестов и затем все 11 сценариев файлов после последней правки, 2 browser load. Полный CI и сборки кандидата ещё выполняются.
- Не проверены: обмен большим файлом на реальном homeserver/с Element, установленная Windows 0.5.7, SAF/Share и память на физическом Android. Сборка/тесты не заменяют эти проверки. Возобновления после закрытия процесса нет; требуется свободное место для временных файлов. При аварийном завершении зашифрованный временный файл может остаться до очистки кеша.

[Устройство и ограничения](docs/LARGE_FILES_SERVER.md). Артефакты и итоги проверки кандидата будут зафиксированы после сборки.

## Группировка Windows — 0.5.6

**0.5.6 опубликована 18 ноября 2026 в 05:42 МСК:** [релиз](https://github.com/VirusGrip/MatrixGram/releases/tag/v0.5.6), [Windows x64](https://github.com/VirusGrip/MatrixGram/releases/download/v0.5.6/MatrixGram_0.5.6_x64-setup.exe), [Android arm64](https://github.com/VirusGrip/MatrixGram/releases/download/v0.5.6/MatrixGram-0.5.6-android-arm64.apk). Пользователь подтвердил решение на копии настоящего MatrixGram 0.5.4: при сортировке диспетчера задач по памяти все дочерние WebView2 находятся внутри группы **MatrixGram**, общая память суммируется, обычный профиль с чатами сохранён. Это группа отдельных процессов, sandbox сохраняется.

Решение — Windows package identity через небольшой sparse MSIX с внешним расположением exe. На Windows 11 10.0.26200 / WebView2 157.0.4341.46 проверены регистрация, запуск, удаление временного доверия сертификату и замена внешнего exe без перерегистрации. После удаления доверия и замены exe пользователь снова подтвердил общую группу и профиль. 18 ноября пользователь проверил обычную установку локального 0.5.6: WebView2 внутри MatrixGram при сортировке по памяти, чаты сохранены, тестовое уведомление и переход по нему работают. SHA-256 установленного EXE совпал с payload кандидата. Нативно подтверждены зарегистрированный пакет со статусом Ok, настроенная привязка и отсутствие временного доверия/приватного ключа. Перезагрузка Windows и Windows 10 пока не проверены.

В исходники 0.5.6 добавлены:

- Неизменяемый подписанный компонент identity 1.0.0.0 с RFC3161 timestamp. Версия компонента не следует версии приложения. В Git хранятся только публичный сертификат и пакет; приватный ключ создания уничтожен. Платный сертификат и новые Secrets не нужны; это не публичный Authenticode-сертификат для EXE.
- Явное согласие пользователя и UAC при первой настройке. Узкий помощник временно добавляет только встроенный сертификат в LocalMachine/TrustedPeople, удаляет добавленное доверие после завершения/исчезновения родителя/тайм-аута. Предсуществующее доверие не удаляется. Корневые CA не меняются.
- NSIS hooks сохраняют регистрацию и сам узел папки приложения при `/UPDATE`; обычное удаление снимает только собственную привязку. Тихая первая установка не выдаёт себе согласие. После обновления настройка доступна из приложения: Настройки → Группировка процессов Windows → Настроить группировку. Для применения нужен полный выход и новый запуск.
- Windows toast выбирает notifier с учётом package identity; в настройках есть «Тестовое уведомление» для ручной проверки без отправки сообщений другим людям. Реальный тестовый toast и клик после локальной установки подтверждены пользователем.

Локально пройдены 54 Rust-теста, 43 frontend unit, 60 browser IPC-сценариев, 2 release-tool теста, fmt/Clippy/policy и проверка всех workflow/version metadata. Проверены криптографическая подпись MSIX/публичный signer/timestamp, компиляция помощника в Windows PowerShell 5 и PowerShell 7, реальные NSIS hooks на изолированной файловой fixture: ID папки сохраняется при обновлении, собственная папка удаляется при uninstall, тихий запуск не добавляет доверие и не регистрирует пакет. Это не замена проверке финального установщика на устройстве.

## Изменения 0.5.5

- По согласованию пользователя добавлен общий счётчик памяти в настройки Windows: суммарная частная резидентная ОЗУ всего дерева MatrixGram, включая WebView2, число процессов и раскрываемая таблица PID/памяти.
- Нативный сбор без PowerShell, внешних помощников и прав администратора: Toolhelp snapshot + PDH с английскими именами счётчиков для локализованной Windows. Обрабатываются одноимённые WebView2, проверяются PID при чтении и время создания процессов против повторного использования PID. Чужие приложения в результат не входят.
- Данные собираются в blocking worker; backend объединяет близкие запросы кешем на 3 секунды. UI опрашивает раз в 5 секунд, прекращает опрос при закрытии настроек и скрытии документа. При ошибке прежняя цифра убирается, неполный замер видимо отмечается. Не используется сумма working set с повторно учтёнными общими страницами.
- На запущенном MatrixGram 0.5.4 нативный сборщик 0.5.5 измерил 7 процессов без пропусков. [Сверка с независимым счётчиком Windows](docs/memory-0.5.5-live.json): оба последовательных замера дали 157,35 МиБ. Это проверка сборщика на живом клиенте, не ручная проверка установленной 0.5.5.
- Добавлены нативные проверки изоляции деревьев/повторного PID, одинаковых имён PDH, неполных данных, реального замера текущего процесса и освобождения handles после повторных замеров. Browser IPC проверяет общую сумму/таблицу, обновление/закрытие, скрытие окна, неполный замер и ошибку без устаревшей цифры.

NSIS регистрирует протокол; portable без регистрации не гарантирует запуск из сохранённого уведомления.

## Исправления 0.5.3

- Имена и аватары из SDK передаются в одной IPC-странице с событиями; UI не показывает известного отправителя сначала логином. Профили и права хранятся по комнате и аккаунту, обновляются даже state-only sync. История запрашивает членство только для отправителей страницы; имена отсутствующих локально участников берутся из отдельного state в ответе `/messages`.
- При открытии убран `roomDetails`, включавший сетевую загрузку всего списка участников, закреплений и настроек. Свежая история повторно используется 60 секунд без повторного чтения SQLite; более поздний запрос обновляет уже видимую историю. После восстановления ключей свежесть сбрасывается. Резервная копия ключей запрашивается только при недостающих ключах; ожидание ограничено 10 секундами.

## Сохранённые функции и ограничения

Сохранены оформление по примеру Telegram, ПАПКИ, поиск пользователей, необязательное E2EE/recovery/import/export, расшифрованное превью в памяти, аватары DM, локальные подписи, закрепление чатов, выбор/пересылка до 100 сообщений, медиа/голосовые, профили/аккаунты, 1:1 WebRTC. [Замеры оптимизации 0.5.1](docs/PERFORMANCE.md) остаются историческим измерением; не выдаются за новые native/Android-замеры 0.5.2. Synapse, PostgreSQL и TURN не менялись.

Переход 0.5.2 → следующая версия в реальном Windows installer и на Android пока не проверялся. Android HTTPS/Keystore/permissions/lifecycle и звонки на телефоне также требуют проверки. Нет фонового push/foreground call service, SAS/QR, UI создания новой backup, OIDC/SSO, групповых MatrixRTC, синхронизации папок/подписей, durable outbox/resumable upload и Authenticode. Неактивные аккаунты не синхронизируются одновременно. Декодированная E2EE-история не пишется в открытый UI cache, обычный кеш сохраняется после logout; безопасного стирания нет.
